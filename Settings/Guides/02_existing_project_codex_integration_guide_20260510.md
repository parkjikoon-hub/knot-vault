# 02. 기존 프로그램에 Codex를 적용하는 방법

작성일: 2026-05-10

## 1. 기본 원칙

이미 개발한 프로그램에는 `핵심 기능을 갈아엎는 방식`으로 AI를 넣지 않는 것이 좋습니다.

좋은 순서는 다음과 같습니다.

1. 기존 흐름 분석
2. AI를 붙일 수 있는 가장 작은 지점 선택
3. 추천/보조 기능 1개만 PoC로 구현
4. 실패 시 기존 수동 흐름으로 안전 복귀
5. 검증 후 범위 확대

## 2. 어디에 붙이면 좋은가

기존 프로그램에서 AI를 붙이기 좋은 대표 지점은 아래와 같습니다.

- 저장 직전 분류 추천
- 파일명/제목 추천
- OCR 후처리
- 검색용 키워드 생성
- 로그 분석
- 관리자용 운영 보조

반대로 처음부터 피하는 것이 좋은 지점:

- 로그인/인증
- 결제
- 실시간 카메라/센서 처리
- 파일 업로드 핵심 경로
- 보안 정책 결정

## 3. 실제 적용 절차

### 3-1. 1단계: 분석

AI 도구에게 먼저 현재 구조를 분석시킵니다.

#### Claude Code / Codex / Gemini 공통 분석 프롬프트

```text
내 프로젝트를 먼저 분석해줘.

목표:
OpenAI Codex를 백엔드 AI 작업 엔진으로 붙이려고 한다.

먼저 코드는 수정하지 말고 아래만 분석해줘.
1. 현재 프론트엔드와 백엔드 구조
2. AI를 붙이기 좋은 지점 3개
3. 그중 가장 작은 PoC로 시작하기 좋은 1개
4. 기존 흐름을 거의 안 깨는 구현 방식
5. 보안상 주의점

비개발자도 이해할 수 있게 쉽게 설명해줘.
```

### 3-2. 2단계: PoC 설계

분석이 끝나면, 작은 기능 1개만 대상으로 설계를 시킵니다.

#### PoC 설계 프롬프트

```text
분석 결과를 바탕으로, 최소 기능 PoC를 설계해줘.

조건:
1. 기존 핵심 흐름은 유지
2. AI 기능은 1개만 추가
3. 실패하면 기존 수동 흐름으로 자동 복귀
4. 새 API 엔드포인트, 입력/출력 구조, 예외 처리, 로그 전략 포함
5. 구현 순서를 단계별로 설명

아직 코드는 수정하지 말고 설계안만 제시해줘.
```

### 3-3. 3단계: 구현

설계가 적절하면 실제 구현을 시킵니다.

#### 구현 프롬프트

```text
방금 설계한 PoC를 실제로 구현해줘.

구현 요구사항:
1. AI 추천용 API 추가
2. 응답을 기존 화면의 기본값으로 반영
3. 추천 실패 시 기존 수동 흐름 유지
4. 타임아웃, 예외 처리, 사용자 메시지 처리
5. 변경한 파일과 이유를 쉽게 설명
6. 테스트 방법 제시

기존 코드 구조를 크게 흔들지 말고 작은 단위로 구현해줘.
```

### 3-4. 4단계: 보안 및 실측 검증

#### 리뷰 프롬프트

```text
이번 AI 연동 구현을 보안과 운영 관점에서 다시 검토해줘.

특히 아래를 확인해줘.
1. 사용자 입력을 그대로 명령 실행에 쓰지 않는지
2. AI 엔진 접근 범위가 제한되는지
3. 개인정보와 민감한 본문 로그가 남지 않는지
4. 실패 시 수동 모드로 안전 복귀하는지
5. 실제 실행 환경에서 도움말, 응답 형식, 오류를 검증했는지

문제점이 있으면 우선순위별로 정리해줘.
```

## 4. "코드 분석 + 실측" 체크리스트

기존 프로젝트에 붙일 때는 아래를 꼭 실제로 확인해야 합니다.

1. `codex --help` 또는 `codex.cmd --help`가 현재 환경에서 어떻게 보이는가
2. `codex exec --help`의 실제 옵션이 문서와 같은가
3. JSON 출력 형식이 실제로 무엇인가
4. 권한/경로/환경변수 문제는 없는가
5. 네트워크/인증 제약은 없는가
6. 실패 시 앱이 어디까지 영향을 받는가

[산출근거: 로컬 실측에서 도움말은 확인됐지만 실제 `exec --json` 실행은 권한 오류가 발생했으므로, 분석만으로는 실제 통합 가능성을 확정할 수 없다고 판단함]

## 5. 교수님이 실제로 많이 쓰게 될 짧은 지시문

### A. 분석용

```text
내 프로젝트를 읽고, Codex를 백엔드 AI 엔진으로 붙이기에 가장 적절한 위치를 먼저 찾아줘. 아직 수정하지 말고 분석만 해줘.
```

### B. 설계용

```text
내 프로젝트에 맞는 Codex 연동 아키텍처를 제안해줘. 너무 크게 하지 말고 최소 기능부터 시작하는 방안을 원해.
```

### C. 구현용

```text
Codex 연동 최소 기능을 실제로 구현해줘. 기존 구조를 해치지 않는 선에서 작은 단위로 작업해줘.
```

### D. 검증용

```text
방금 구현한 Codex 연동 기능이 실제로 어떤 흐름으로 동작하는지, 비개발자도 이해할 수 있게 단계별로 설명해줘.
```

## 6. 가장 좋은 실무 원칙

기존 프로그램에 AI를 넣을 때 가장 좋은 방식은:

`핵심 기능을 바꾸는 것`이 아니라  
`핵심 기능 앞뒤에 추천/보조/후처리 계층을 붙이는 것`

입니다.

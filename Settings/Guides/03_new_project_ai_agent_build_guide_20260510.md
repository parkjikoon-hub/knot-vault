# 03. 신규 프로젝트를 AI 에이전트 구조로 개발하는 방법

작성일: 2026-05-10

## 1. 기본 개념

신규 프로젝트는 처음부터 아래 3계층으로 설계하면 좋습니다.

1. 사용자 앱 계층
2. 일반 백엔드 계층
3. AI 에이전트 계층

이 구조가 좋은 이유는, 나중에 AI 기능을 추가하거나 바꿀 때 전체 시스템을 뜯어고치지 않아도 되기 때문입니다.

## 2. 권장 아키텍처

### 2-1. 사용자 앱 계층

역할:

- 화면 표시
- 사용자 입력
- 결과 확인

예:

- 웹앱
- 모바일 앱
- 데스크톱 앱

### 2-2. 일반 백엔드 계층

역할:

- 로그인
- 권한
- 데이터베이스
- API
- 작업 이력
- AI 요청 중계

### 2-3. AI 에이전트 계층

역할:

- 분류
- 추천
- 문서 후처리
- 코드/설정 제안
- 반복 작업 자동화

## 3. 신규 프로젝트에서 가장 먼저 넣기 좋은 AI 기능

처음에는 아래 중 `하나만` 고르는 것이 좋습니다.

- 문서 분류 추천
- 파일명 추천
- OCR 후처리
- 키워드 생성
- 요약
- 로그 1차 해석

## 4. 신규 프로젝트를 시작할 때 먼저 정리해야 할 질문

1. 사용자가 어떤 화면에서 무엇을 요청하는가
2. AI가 판단해야 하는 지점은 어디인가
3. AI가 실패하면 서비스는 어떻게 계속 동작해야 하는가
4. AI 결과는 추천인가, 자동 실행인가
5. 개인정보가 포함되는가
6. 사람이 최종 확인해야 하는가

## 5. 신규 프로젝트용 AI 지시문

### 5-1. 아키텍처 설계 요청

```text
새 프로젝트를 설계하려고 한다.

목표:
일반 백엔드와 별도로 Codex 같은 AI 에이전트 계층을 두고,
문서 분류/추천/자동화 기능을 붙인 구조로 만들고 싶다.

다음 항목으로 아키텍처를 설계해줘.
1. 프론트엔드
2. 일반 백엔드
3. AI 에이전트 계층
4. 데이터 흐름
5. 장애 시 복구 방식
6. 보안상 주의점

비개발자도 이해할 수 있게 설명해줘.
```

### 5-2. MVP 범위 축소 요청

```text
아키텍처를 너무 크게 잡지 말고 MVP 기준으로 줄여줘.

조건:
1. 첫 버전은 AI 추천 기능 1개만 포함
2. AI 실패 시 수동 입력으로 계속 진행 가능
3. 파일 구조와 API 구조를 단순하게 유지
4. 나중에 추천 기능을 더 추가할 수 있게 확장성은 확보

MVP 기능, 폴더 구조, API 설계, 구현 순서를 제안해줘.
```

### 5-3. 초기 코드 골격 생성 요청

```text
위 MVP 설계를 바탕으로 실제 프로젝트 초기 구조를 만들어줘.

포함할 것:
1. 프론트엔드 기본 화면
2. 일반 백엔드 API
3. AI 추천 요청용 엔드포인트
4. 실패 시 수동 입력으로 돌아가는 UI
5. README와 실행 방법

각 파일의 역할도 쉽게 설명해줘.
```

### 5-4. 구조 검토 요청

```text
지금 구현된 구조를 검토해줘.

우선순위는 아래 순서로 봐줘.
1. 보안
2. 장애 대응
3. 유지보수성
4. 비개발자도 운영 가능한 구조인지
5. 과도하게 복잡하지 않은지

문제가 있으면 심각도 순서로 정리해줘.
```

## 6. Claude Code / Codex / Gemini 역할 분담 추천

### Claude Code

- 기존 코드 분석
- 실제 코드 수정
- 테스트와 리팩토링
- 프로젝트 구조 적응

### Codex

- 별도 AI 작업 엔진
- 백그라운드 작업 처리
- 코드/문서/파일/명령 기반 보조
- 비대화형 작업 실행

### Gemini

- 아이디어 정리
- 요구사항 재정리
- 문서 초안
- 비교안 탐색

[산출근거: 각 도구를 일반적으로 활용하는 역할 특성을 기준으로 정리했으며, 실제 지원 범위는 계정·배포 환경에 따라 다를 수 있음]

## 7. 신규 프로젝트에서 가장 좋은 시작 전략

1. AI가 꼭 필요한 판단 기능 1개만 정한다.
2. 일반 백엔드와 AI 계층을 분리한다.
3. 실패 시 수동 흐름을 먼저 설계한다.
4. 그 다음 구현한다.
5. 마지막에 실제 환경에서 CLI/API를 실측 검증한다.

## 8. 한 줄 결론

신규 프로젝트는 처음부터 `사용자 앱 / 일반 백엔드 / AI 에이전트 계층`으로 나누어 설계하면, AI 기능을 억지로 끼워 넣는 것보다 훨씬 안정적이고 확장 가능한 구조를 만들 수 있다.
